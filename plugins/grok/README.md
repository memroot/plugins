# Memroot for Grok Build

This is the complete, self-contained Memroot plugin root, version `0.5.0`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production MCP server with Grok at user scope (`grok mcp add --scope user --transport http memroot https://api.memroot.dev/mcp`); its tools provide explicit save and retrieval. Authorize it once inside Grok: run `/mcps`, select memroot and press `i` to sign in in the browser. Grok runs the OAuth flow itself and keeps the tokens in its own store (`~/.grok/mcp_credentials.json`); Memroot never reads or copies them. Setup preserves an existing `memroot` entry that differs, and `grok mcp remove memroot` removes the registration. Grok also reads the `memroot` server that Claude Code setup wrote to `~/.claude.json`, but it still needs its own authorization in `/mcps`. Setup also installs a global instruction file, `~/.grok/rules/memroot.md`, that names Memroot the default durable memory layer for every session.

Hooks read bounded native envelopes and metadata only, never transcript content or the network. SessionStart (Grok: the reminder) and PreToolUse register the authoritative native session, including recovery when a startup transcript path is null. The PreToolUse handler remains silent for unrelated tools and never grants permission; supported direct Memroot memory tools are denied when the selected project ID is missing or mismatched. SessionEnd/PostCompact enqueue only with explicit capture consent v4 and a current project binding, then start the detached bundled worker. Jobs contain private identifiers, paths, project/account scope, byte offsets and integrity digests, never raw text. A manual switch seals the old segment through a bounded local snapshot worker; no model/network call runs during that seal. Sealed work waits for the next agreed native end/compaction trigger. Older capture consent is never expanded automatically: review `memroot capture on`, then reselect the current project from the current EOF.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 3 memories per capture and 10 per 24 hours. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

Grok ignores stdout for passive hook events, including SessionStart, and discards UserPromptSubmit output, so this bundle declares a PostToolUse hook for the session reminder (timeout 3 s), a second PostToolUse `memory-mirror` hook that nudges Grok toward Memroot when it writes to its own built-in memory (non-blocking, at most once per session, no event content echoed), a SessionEnd hook (timeout 5 s; it typically returns in about 25 ms) and a PostCompact hook with a 5 s timeout that runs the same script once a compaction is done (Grok treats PostCompact as a passive event that blocks nothing). For a Grok session the worker reads `updates.jsonl`, which Grok only appends to; `chat_history.jsonl` is rewritten at every compaction and is excluded from project-scoped capture; unavailable append-only updates fail safely. Grok also loads the Claude Code plugin from `~/.claude`. When both plugins are installed they share the name `memroot` and Grok 1.0.46 loads only the Claude Code copy, so no trusted Grok reminder handle is delivered and the project command remains bundled for Claude. Project selection and project-scoped capture are unsupported in that coexistence path in this release; do not treat old tool availability as support for the new project workflow. Use the dedicated Grok plugin path or Claude Code/Codex. A user-level `~/.grok/hooks` entry that does not depend on which plugin copy Grok loads is the planned follow-up. The reminder is emitted once per session and is not emitted again after Grok compacts the conversation, so a long session can lose it. It uses the documented Claude-compatible plugin manifest.

Inspect the installed plugin through the agent's native plugin interface.

Select a product for this chat with the project skill (Claude Code: `/memroot:project`; Codex: `$memroot-project` or `/skills`; Grok: select `memroot-project` in the native skill picker). Use `list`, `use [NAME]`, `create NAME`, or `status`. `use` with no name binds the remembered default — the last project explicitly selected for this agent and account — or the sole authorized project, checked against the live project list, and prints `Using default project "<name>" (<projectId>).`; `status` reports a `defaultProject` hint beside the selection. Several repositories may share one project, and a folder never selects one. A session choice survives resume/compact, and changing one chat does not change another. Project commands use the separately authorized Memroot CLI connection and do not enable capture.
