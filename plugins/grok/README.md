# Memroot for Grok Build

This is the complete, self-contained Memroot plugin root, version `0.1.0-alpha.9`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production MCP server with Grok at user scope (`grok mcp add --scope user --transport http memroot https://api.memroot.dev/mcp`); its tools provide explicit save and retrieval. Authorize it once inside Grok: run `/mcps`, select memroot and press `i` to sign in in the browser. Grok runs the OAuth flow itself and keeps the tokens in its own store (`~/.grok/mcp_credentials.json`); Memroot never reads or copies them. Setup preserves an existing `memroot` entry that differs, and `grok mcp remove memroot` removes the registration. Grok also reads the `memroot` server that Claude Code setup wrote to `~/.claude.json`, but it still needs its own authorization in `/mcps`.

Hooks only read the stdin envelope (at most 64 KiB; the SessionEnd and PostCompact hook at most 1 MiB, because a compaction event can carry the summary of the conversation; waiting at most 500 ms) and never echo event fields. A larger envelope is dropped, which means no capture for that trigger; the next trigger of the session captures the same turns. They print nothing on SessionEnd or PostCompact, never open a transcript and make no network request. The PostToolUse hook prints one static sentence about memory retrieval once per session, after the first tool call that ran, and only when setup recorded the MCP registration; otherwise it prints nothing. Its once-per-session marker is an empty file named by a salted hash of the session id (0600 under `$XDG_STATE_HOME/memroot/capture/reminded`; markers older than 14 days are removed when a later session is marked). It runs after every tool call and typically returns in about 30 ms. When the user has opted in with `memroot capture on`, the SessionEnd hook, and the PostCompact hook once Grok has compacted a session that is still open, write one small job file per session (identifiers, paths and the trigger only; 0600 under `$XDG_STATE_HOME/memroot/capture`) and start the bundled `scripts/capture-worker.mjs` fully detached, resolved next to the hook script itself. Both run the same script. The PostCompact hook reads none of the event's content fields: the compaction summary is never read, stored or logged. Without consent the hooks do nothing. Capture at compaction needs its own agreement, which `memroot capture on` of `0.1.0-alpha.7` or later records in a second file (`~/.memroot/capture-compaction.json`) bound to the consent; consent given with an earlier version, or rewritten by one, covers session ends only.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 3 memories per capture and 10 per 24 hours. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

Grok ignores stdout for passive hook events, including SessionStart, and discards UserPromptSubmit output, so this bundle declares a PostToolUse hook for the session reminder (timeout 3 s), a SessionEnd hook (timeout 5 s; it typically returns in about 25 ms) and a PostCompact hook with a 5 s timeout that runs the same script once a compaction is done (Grok treats PostCompact as a passive event that blocks nothing). For a Grok session the worker reads `updates.jsonl`, which Grok only appends to; `chat_history.jsonl` is rewritten at every compaction and is read only when `updates.jsonl` holds no message. Grok also loads the Claude Code plugin from `~/.claude`. When both plugins are installed they share the name `memroot` and Grok 1.0.46 loads only the Claude Code copy, so its SessionEnd and PostCompact hooks capture the Grok session and no session reminder is shown in Grok; the MCP tools and skills still work there. A user-level `~/.grok/hooks` entry that does not depend on which plugin copy Grok loads is the planned follow-up. The reminder is emitted once per session and is not emitted again after Grok compacts the conversation, so a long session can lose it. It uses the documented Claude-compatible plugin manifest.
