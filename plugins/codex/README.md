# Memroot for Codex

This is the complete, self-contained Memroot plugin root, version `0.6.0`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

Codex plugin support is a Codex feature and must be enabled. If `codex plugin list` fails or setup cannot find the plugin manager, run `codex features enable plugins` and restart Codex, then re-run `npx memroot@latest setup`.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production remote MCP server with Codex and opens native OAuth sign-in when needed. The MCP tools provide retrieval and automatic saving after authorization. Setup also maintains a managed `<!-- memroot:start -->` … `<!-- memroot:end -->` block in `~/.codex/AGENTS.md` (or `AGENTS.override.md` when that file is used) that names Memroot the default durable memory layer; content outside the markers is untouched.

Hooks read bounded native envelopes and metadata only, never transcript content or the network. The project in use is the one selected on this computer (`~/.memroot/project-selection.json`); no per-session state decides it. SessionStart (`startup`, `resume`, `clear`, `compact` and `fork`) adds one line naming the selected project and its `project_id`, or the exact command to select one, and, once an account is signed in on this computer, starts a detached background check that selects the account's only project when none is selected. The PreToolUse project guard stays silent for unrelated tools. With a project selected it approves every Memroot memory call (`memory_retrieve`, `memory_create`, `memory_archive`, `memory_restore`) and sets its `project_id` to the selected project, so memory works without a permission prompt. With nothing selected it denies the call with the command to select one. Capture triggers (SessionEnd, PreCompact, PostCompact, Stop and a SessionStart `resume`) queue a job only after you agreed to the current capture terms, record the project selected when they fire, and start the detached bundled worker; a turn end queues a capture after 8 turn ends or 20 minutes, and work queued while no project is selected waits for the first selection. A forked session (SessionStart `fork`) records where the copied history ends, so that history is never captured again. Codex has no idle event, so an idle session is captured at its next turn end, compaction or session end. Capture only reads turns written after it was turned on. Jobs hold identifiers, paths, the project scope and a turn cursor, never raw text. A PostToolUse `memory-mirror` hook tells the agent to save the same lesson to Memroot each time it writes its own built-in memory (a patch or a shell write into `~/.codex/memories/` or the Codex home `AGENTS.md`), or to select a project first when none is selected; it is non-blocking, nudges once per identical write in a session and echoes no event content. A UserPromptSubmit `prompt-nudge` hook asks the agent on every prompt to check Memroot first and to save durable lessons to Memroot on its own; it is non-blocking, keeps no state and neither reads nor echoes prompt content.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 50 memories per capture run and 500 per rolling 24 hours; the service enforces your plan's memory limit. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

The SessionStart hook supplies a short static context about retrieving memory first and saving durable lessons automatically (timeout 3 s). The SessionEnd hook has Codex's maximum 3 s timeout and typically returns in about 25 ms. The PostCompact hook has a 3 s timeout and returns as fast; it runs after the compaction is done, prints nothing and exits 0, which Codex does not treat as a request to stop (only `continue: false` on standard output is). The Stop hook has a 5 s timeout, prints `{}` (Codex expects JSON from a Stop hook that exits 0) and only queues a debounced job, so it never asks Codex to continue. The PreCompact hook (new in 0.6.0, timeout 5 s) queues the same capture before the compaction; it prints nothing and exits 0, so it never blocks the compaction, and the PostCompact run after it finds no new turns. Codex only appends to the rollout file, so the turns from before a compaction stay in it. Codex has no failure recall nudge and no subagent capture in 0.6.0: its PostToolUse `tool_response` has no documented exit status, and a SubagentStop probe was not possible in an isolated home (ADR 0008).

After installation, review and trust SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, SessionEnd, PreCompact, PostCompact and Stop through `/hooks` in Codex. Installation does not establish hook trust. PreToolUse was new in 0.2.0; the PostToolUse `memory-mirror` and UserPromptSubmit `prompt-nudge` hooks are new in 0.3.0, and after a plugin update Codex lists them as untrusted and skips them until they are trusted there — the same `codexHookTrustStep` note printed by `memroot setup`. The Stop and PreCompact hooks are new in 0.6.0 and need the same trust step. PreToolUse approves Memroot memory calls with the selected `project_id`, or denies them when nothing is selected; it does not act on any other tool. Hook commands use `PLUGIN_ROOT`.

Setup owns the single user-scope `memroot` MCP registration; this plugin intentionally declares no second MCP server.

Inspect the installed plugin through the agent's native plugin interface.

Select the project once with the project skill (Claude Code: `/memroot:project`; Codex: `$memroot-project` or `/skills`; Grok: select `memroot-project` in the native skill picker) or with the command the session context gives. Use `status`, `list`, `use [NAME]` or `create NAME`. The selection applies to every session and agent on this computer until you change it. `use` with no name keeps a still-valid selection or selects the account's only project, and never picks one of several; the agent may run it on its own when nothing is selected and asks you when there are several projects. Several repositories may share one project, and a folder never selects one. Project commands use the separately authorized Memroot CLI connection and do not change capture.
