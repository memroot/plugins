# Memroot for Codex

This is the complete, self-contained Memroot plugin root, version `0.1.0-alpha.9`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production remote MCP server with Codex and opens native OAuth sign-in when needed. The MCP tools provide explicit save and retrieval after authorization.

Hooks only read the stdin envelope (at most 64 KiB; the SessionEnd and PostCompact hook at most 1 MiB, because a compaction event can carry the summary of the conversation; waiting at most 500 ms) and never echo event fields. A larger envelope is dropped, which means no capture for that trigger; the next trigger of the session captures the same turns. They print nothing on SessionEnd or PostCompact, never open a transcript and make no network request. When the user has opted in with `memroot capture on`, the SessionEnd hook, and the PostCompact hook once Codex has compacted a session that is still open, write one small job file per session (identifiers, paths and the trigger only; 0600 under `$XDG_STATE_HOME/memroot/capture`) and start the bundled `scripts/capture-worker.mjs` fully detached, resolved next to the hook script itself. Both run the same script. The PostCompact hook reads none of the event's content fields: the compaction summary is never read, stored or logged. Without consent the hooks do nothing. Capture at compaction needs its own agreement, which `memroot capture on` of `0.1.0-alpha.7` or later records in a second file (`~/.memroot/capture-compaction.json`) bound to the consent; consent given with an earlier version, or rewritten by one, covers session ends only.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 3 memories per capture and 10 per 24 hours. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

The SessionStart hook supplies a short static context about memory retrieval (timeout 3 s). The SessionEnd hook has Codex's maximum 3 s timeout and typically returns in about 25 ms. The PostCompact hook has a 3 s timeout and returns as fast; it runs after the compaction is done, prints nothing and exits 0, which Codex does not treat as a request to stop (only `continue: false` on standard output is). Codex only appends to the rollout file, so the turns from before a compaction stay in it.

After installation, review and trust the three hooks through `/hooks` in Codex. Plugin installation does not establish hook trust, and Codex skips untrusted hooks. Trust is pinned per hook definition (event, position and handler), and existing entries of `hooks/hooks.json` are kept unchanged across releases (the SessionStart entry is unchanged from `0.1.0-alpha.1`, the SessionEnd entry is unchanged in this release), so they stay trusted after an upgrade. The PostCompact entry is new in `0.1.0-alpha.7`: after an upgrade Codex lists it as untrusted and skips it until you trust it in `/hooks`, and until then sessions are captured at their end only (checked with Codex 0.160.0 on October 10, 2026: after the upgrade steps that `memroot setup` runs, the two earlier hooks were still trusted and the new one was not). The compatibility manifest relies on default `hooks/hooks.json` discovery; hook commands use `PLUGIN_ROOT`.

Setup owns the single user-scope `memroot` MCP registration; this plugin intentionally declares no second MCP server.

Inspect the installed plugin through the agent's native plugin interface.
