# Memroot for Codex

This is the complete, self-contained Memroot plugin root, version `0.3.0`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production remote MCP server with Codex and opens native OAuth sign-in when needed. The MCP tools provide explicit save and retrieval after authorization. Setup also maintains a managed `<!-- memroot:start -->` … `<!-- memroot:end -->` block in `~/.codex/AGENTS.md` (or `AGENTS.override.md` when that file is used) that names Memroot the default durable memory layer; content outside the markers is untouched.

Hooks read bounded native envelopes and metadata only, never transcript content or the network. SessionStart (Grok: the reminder) and PreToolUse register the authoritative native session, including recovery when a startup transcript path is null. The PreToolUse handler remains silent for unrelated tools and never grants permission; supported direct Memroot memory tools are denied when the selected project ID is missing or mismatched. SessionEnd/PostCompact enqueue only with explicit capture consent v4 and a current project binding, then start the detached bundled worker. Jobs contain private identifiers, paths, project/account scope, byte offsets and integrity digests, never raw text. A manual switch seals the old segment through a bounded local snapshot worker; no model/network call runs during that seal. Sealed work waits for the next agreed native end/compaction trigger. Older capture consent is never expanded automatically: review `memroot capture on`, then reselect the current project from the current EOF. A new PostToolUse `memory-mirror` hook nudges the agent toward Memroot when it writes to its own built-in memory; it is non-blocking, fires at most once per session and echoes no event content. A new UserPromptSubmit `prompt-nudge` hook recalls project memory on the session's first prompt; it is non-blocking, fires at most once per session and neither reads nor echoes prompt content.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 3 memories per capture and 10 per 24 hours. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

The SessionStart hook supplies a short static context about memory retrieval (timeout 3 s). The SessionEnd hook has Codex's maximum 3 s timeout and typically returns in about 25 ms. The PostCompact hook has a 3 s timeout and returns as fast; it runs after the compaction is done, prints nothing and exits 0, which Codex does not treat as a request to stop (only `continue: false` on standard output is). Codex only appends to the rollout file, so the turns from before a compaction stay in it.

After installation, review and trust SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, SessionEnd and PostCompact through `/hooks` in Codex. Installation does not establish hook trust. PreToolUse was new in 0.2.0; the PostToolUse `memory-mirror` and UserPromptSubmit `prompt-nudge` hooks are new in 0.3.0, and after a plugin update Codex lists them as untrusted and skips them until they are trusted there — the same `codexHookTrustStep` note printed by `memroot setup`. PreToolUse registers native session metadata before tools and denies only supported direct Memroot memory calls; it never replaces normal native tool permission. `memory-mirror` only nudges toward Memroot when Codex writes to its own built-in memory; it is non-blocking, fires at most once per session and echoes no event content. Hook commands use `PLUGIN_ROOT`.

Setup owns the single user-scope `memroot` MCP registration; this plugin intentionally declares no second MCP server.

Use `list`, `use [NAME]`, `create NAME`, or `status`. `use` with no name binds the remembered default — the last project explicitly selected for this agent and account — or the sole authorized project, checked against the live project list, and prints `Using default project "<name>" (<projectId>).`; `status` reports a `defaultProject` hint beside the selection. Several repositories may share one project, and a folder never selects one. A session choice survives resume/compact, and changing one chat does not change another. Project commands use the separately authorized Memroot CLI connection and do not enable capture.
