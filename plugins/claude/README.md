# Memroot for Claude Code

This is the complete, self-contained Memroot plugin root, version `0.6.0`. The native agent plugin manager installs this folder from the public Memroot plugin marketplace and owns subsequent updates. Node.js is the only runtime requirement. Every script in `scripts/` is generated from the Memroot CLI source and bundled with its dependencies; no script refers to `npx`, the npm cache or files outside this bundle.

The memroot-status skill and `node scripts/status.mjs` explain this release's capabilities. Setup registers the production MCP server with Claude Code (authorize it with `/mcp`); its tools provide retrieval and automatic saving. Setup also installs a global instruction file, `~/.claude/rules/memroot.md`, that names Memroot the default durable memory layer for every session.

Hooks read bounded native envelopes and metadata only, never transcript content or the network. The project in use is the one selected on this computer (`~/.memroot/project-selection.json`); no per-session state decides it. SessionStart (`startup`, `resume`, `clear`, `compact` and `fork`) adds one line naming the selected project and its `project_id`, or the exact command to select one, and, once an account is signed in on this computer, starts a detached background check that selects the account's only project when none is selected. The PreToolUse project guard stays silent for unrelated tools. With a project selected it approves every Memroot memory call (`memory_retrieve`, `memory_create`, `memory_archive`, `memory_restore`) and sets its `project_id` to the selected project, so memory works without a permission prompt; your own deny and ask rules still apply, so add an `ask` rule for the `mcp__memroot__*` tools if you want to be prompted. With nothing selected it denies the call with the command to select one. Capture triggers (SessionEnd, PreCompact, PostCompact, Stop, SubagentStop, the `idle_prompt` Notification and a SessionStart `resume`) queue a job only after you agreed to the current capture terms, record the project selected when they fire, and start the detached bundled worker; a turn end queues a capture after 8 turn ends or 20 minutes, the idle prompt at most every 5 minutes, and work queued while no project is selected waits for the first selection. A forked session (SessionStart `fork`) records where the copied history ends, so that history is never captured again. Capture only reads turns written after it was turned on. Jobs hold identifiers, paths, the project scope and a turn cursor, never raw text. A PostToolUse `memory-mirror` hook tells the agent to save the same lesson to Memroot each time it writes its own built-in memory (the auto-memory folder, including a relocated `autoMemoryDirectory`), through a file tool or a shell redirection, `tee`, `cp` or `mv` (or to select a project first when none is selected); it is non-blocking, nudges once per identical write in a session and echoes no event content. A PostToolUseFailure `failure-nudge` hook (matcher `Bash`, timeout 3 s) adds one line when a Bash call fails with a non-zero exit code: this may be a known failure, so check Memroot with `memory_retrieve` using the error code or symptom, not the output. It fires once per distinct failure (a salted hash of the exit code and the command's first word) and at most five times a session, only with a project selected and never in a subagent; it matches only the first line of the error (`Exit code N`) and stores or echoes nothing from the call. A UserPromptSubmit `prompt-nudge` hook asks the agent on every prompt to check Memroot first and to save durable lessons to Memroot on its own; it is non-blocking, keeps no state and neither reads nor echoes prompt content.

The bundled worker reads only the referenced session transcript, keeps user and assistant text plus tool names and file paths (never tool output), redacts secrets, personal email addresses and home paths locally and fails closed, runs your own agent CLI headless with no tools to propose memories, validates them, and sends only typed memories labeled session-extracted (not user-attested) to `https://api.memroot.dev/mcp` with the separate Memroot CLI capture connection. Each memory includes up to 3 short evidence quotes (at most 200 characters) from the redacted transcript, repo-relative paths and symbols, the normalized repository remote, and salted hashes of the session id and quoted segments; one retrieval query per capture contains only the repository name. Raw transcripts are never uploaded. At most 50 memories per capture run and 500 per rolling 24 hours; the service enforces your plan's memory limit. A later capture of the same session reads only the turns added since the previous one. `memroot capture off` stops capture and deletes queued work.

The SessionStart hook supplies a short static context about retrieving memory first and saving durable lessons automatically. The SessionEnd hook stays within Claude Code's fixed 1.5 s SessionEnd budget (plugin timeouts cannot raise it); it typically returns in about 25 ms. The PostCompact hook has a 5 s timeout and returns as fast; it runs after the compaction is done, and Claude Code gives PostCompact no way to block or change anything. The Stop and `idle_prompt` Notification hooks have a 5 s timeout, print nothing and only queue a debounced job. The PreCompact hook (new in 0.6.0, timeout 5 s) queues the same capture before the compaction summarizes the history; it prints nothing and never returns a decision, so an automatic compaction is never blocked, and the PostCompact run after it finds no new turns. The SubagentStop hook (new in 0.6.0, timeout 5 s) queues a capture of the parent session, its own transcript and not the subagent's, only when the turn-end rule already allows one (8 turn ends, or 20 minutes with at least 2); it never counts as a turn; it prints nothing and is skipped while `stop_hook_active` is set. Claude Code only appends to the transcript, so the turns from before a compaction stay in it. Grok also loads this plugin from `~/.claude`; under Grok the scripts act for the Grok host and the SessionStart context stays silent.

Inspect the installed plugin through the agent's native plugin interface.

Select the project once with the project skill (Claude Code: `/memroot:project`; Codex: `$memroot-project` or `/skills`; Grok: select `memroot-project` in the native skill picker) or with the command the session context gives. Use `status`, `list`, `use [NAME]` or `create NAME`. The selection applies to every session and agent on this computer until you change it. `use` with no name keeps a still-valid selection or selects the account's only project, and never picks one of several; the agent may run it on its own when nothing is selected and asks you when there are several projects. Several repositories may share one project, and a folder never selects one. Project commands use the separately authorized Memroot CLI connection and do not change capture.
